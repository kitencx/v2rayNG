# v2rayNG UI 重构计划

基线为 kitencx/v2rayNG 的 master，提交 `740f0ba`。手机、Pad、电视分别设计适合设备尺寸和输入方式的界面。三端效果图经项目发起人明确确认后进入实现。电视首轮以 TCL T7M Ultra 为目标。本文是实施计划，工期为单人开发的粗估，构建和真机结果在实施时记录。

## 1. 目标与边界

- **手机端**统一首页、订阅、各协议编辑、路由、分应用代理、资源、备份恢复、日志、检查更新和关于等页面的视觉与交互反馈，保留现有功能入口和操作结果。
- **Pad 端**兼顾横屏和竖屏触控。横屏优先验证列表与连接状态或节点详情并列，竖屏验证窄宽度下的单栏或双栏切换。
- **电视端**用方向键、OK 和返回键完成从零配置到连接的全过程。最终覆盖 App 内核心和高级管理操作。系统组件及依赖摄像头的功能按设备能力验证和展示。
- **共用业务层**沿用现有 VPN、仅代理、Root 启停和切换语义，保持 MMKV 数据、配置格式、导入导出、快捷方式、桌面小组件及外部调用兼容。首轮同一个 APK、同一个 `MainActivity`，从原有手机和电视入口进入。

## 2. 第一步：三端 UI 设计与评审

先查找并选定支持 Android 多端高保真界面的 UI 设计 skill。已找到 Figma 的界面设计能力作为候选，优先用它制作可编辑画板，并导出可直接查看的 PNG 效果图。设计依据是现有页面、功能入口和状态，三端共用视觉语言，各自设计布局与操作路径。

| 设备 | 首轮效果图 | 评审重点 |
|---|---|---|
| 手机 | 竖屏节点首页（断开、已连接）、空状态与导入、设置或节点编辑 | 单手触控、主要操作的位置、节点信息密度 |
| Pad | 横屏双栏首页、竖屏首页、订阅或节点编辑 | 大屏信息利用、横竖屏布局和触控操作连续性 |
| 电视 | 16:9 空配置首页、已配置首页、添加订阅及弹窗的焦点状态 | 远距离可读性、方向键跨区域、OK 确认、返回及焦点恢复 |

评审包包含三端分开的高保真效果图、可编辑稿链接和一份电视遥控焦点标注图。效果图使用示例节点和订阅数据。评审时确认视觉方向、三端布局、主要操作，以及电视焦点和返回规则。修改后更新效果图，按版本复核。

**确认条件**：三端效果图都交付后，由项目发起人在 PR 或对话中明确确认最终版本。确认前仅做现状调研、设计、评审及修订。主题、布局、交互和业务代码的实现从确认后开始。部分设备已确认时，仍等三端方案全部确认再启动实现。

## 3. 确认后的预计改动落点

| 区域 | 文件或目录 | 计划 |
|---|---|---|
| 主题与公共组件 | `ui/compose/Theme.kt`、`Components.kt`、`FormFields.kt`、`Dialog.kt`、`SettingsItem.kt` | 沿用 Compose Material 3，统一色彩、字阶、间距、圆角、按钮/列表/表单/对话框。保留手机夜间模式、动态色及已有布局行为，为电视补充远距可读性和清晰焦点状态 |
| 首页入口 | `ui/main/MainActivity.kt`、`MainScreen.kt`、`MainContract.kt`、`MainViewModel.kt` | 按设备和可用窗口尺寸选择手机、Pad 或电视布局。Pad 根据窗口尺寸和横竖屏变化调整布局。沿用现有状态、动作、导航与 VPN 授权入口，需要补动作时进入现有 action/事件链 |
| 首页组件 | `MainTopBar.kt`、`MainBottomBar.kt`、`MainServerPager.kt`、`MainDrawer.kt` | 手机重做连接区和节点列表，Pad 使用适合大屏触控的多栏布局，电视按确认的方案组织焦点区域与操作区。复用列表数据与动作，把节点的低频操作集中到「更多」 |
| 导入与订阅 | `MainImportMenu.kt`、`ui/subscription/`、`helper/FileChooserHelper.kt` | 电视空首页提供「添加订阅」，复用现有订阅保存、更新与校验。后续补齐可输入配置文本的入口，复用现有批量解析。实测本地选择器、剪贴板和摄像头可用性 |
| 高级页面 | `ui/settings/`、`ui/server/`、`ui/routing/`、`ui/perappproxy/`、`ui/userasset/`、`ui/backup/`、`ui/logcat/` 等 | 用公共组件完成视觉一致性，为需要拖拽的节点、订阅、路由规则及代理链提供遥控排序操作，验证表单、系统输入法和弹窗 |
| 启动与打包 | `AndroidManifest.xml`、`.github/workflows/build.yml` | 沿用已有 TV launcher 声明和 banner，验证 TCL 桌面入口、目标 ABI 和 APK 安装。依 CI 准备现有原生构建输入 |

## 4. 实施里程碑

| 阶段 | 工作内容 | 交付和退出条件 | 粗估 |
|---|---|---|---|
| 1. 三端设计与确认 | 选定设计方法，完成手机、Pad、电视效果图和遥控焦点标注，根据反馈修订 | 项目发起人明确确认三端效果图和交互方案 | 3–5 人日 |
| 2. 建立实施基线 | 准备构建依赖并构建现有 Debug APK，在 TCL 上检查安装、桌面入口、方向键、VPN 授权、输入法及文件选择器 | 基线 APK、三端功能清单、TCL 实机记录 | 1–2 人日 |
| 3. 公共组件与手机、Pad 首页 | 实现已确认的主题、连接区、节点行、按钮和弹窗，落地两端首页 | 节点切换、启停、测速及导入可用，覆盖手机亮暗主题和 Pad 横竖屏 | 2–4 人日 |
| 4. 电视首次连接 | 落地电视首页、焦点和返回规则，复用订阅页完成首次导入 | 空数据的 TCL 上全程用遥控器完成添加订阅、更新、选节点、VPN 授权、连接、测速和断开 | 3–5 人日 |
| 5. 全量页面和高级交互 | 手机和 Pad 逐页覆盖，电视补齐表单、更多菜单、排序、批量管理和设备支持的导入导出 | 三端功能清单逐项对照旧版，新增文案覆盖项目配置的语言 | 5–9 人日 |
| 6. 回归与交付 | 三端验收，覆盖旧版本数据升级、签名条件、服务状态和外部入口 | 可安装 APK、变更清单、回归结果和设备已知限制 | 2–4 人日 |

合计粗估 **16–29 人日**，以单人开发、复用现有业务和服务、首轮在一台 TCL 上验证为前提。评审等待时间另计，三端效果图确认后复核实施工期。

## 5. 电视交互验收

| 场景 | 验收条件 |
|---|---|
| 启动与空状态 | 从电视桌面进入时有可见焦点。空配置默认聚焦「添加配置」，完成订阅更新后能进入节点列表 |
| 分组与节点 | 左右可跨区域，上下可连续浏览和滚动。分组靠明确操作切换。浏览节点只改变焦点，按 OK 才提交选中动作。连接状态、节点选中和遥控焦点可同时辨认 |
| 状态变化 | 关闭弹窗和从编辑页返回时回到触发项。排序、更新和过滤后，按 GUID 或分组 ID 找回焦点，原项消失时转移到相邻有效项或空状态入口 |
| 连接与选节点 | 首次授权允许、拒绝和返回都能恢复焦点。连接时切换节点保留现有服务行为。测速进度和结果可见，失败能回到可操作状态 |
| 排序及表单 | 方向键可到达排序和保存操作。排序后焦点跟随移动项。长表单打开电视输入法后仍能滚到最后一个字段并保存 |
| 返回与系统组件 | 返回键逐层退出弹窗、编辑、首页。退出首页后再次打开，从现有服务状态恢复显示。记录文件选择器、分享和 VPN 授权等系统界面的真机结果 |

## 6. 发布前回归

- **构建**从 `V2rayNG/` 执行 `./gradlew :app:testPlaystoreDebugUnitTest :app:compilePlaystoreDebugKotlin :app:assemblePlaystoreDebug`，并按仓库规则补齐针对性测试、Lint 或 F-Droid 变体验证。
- **设备**用手机覆盖触控、键盘和 TalkBack，用 Pad 覆盖横竖屏、列表与详情切换和旋转后的状态恢复，用 Android TV 模拟器覆盖标准 D-pad 路径，用 TCL T7M Ultra 覆盖厂商桌面、物理遥控器、电视输入法及系统 VPN 对话框。明确记录无法运行的检查。
- **兼容性**先用现网版本建立节点、订阅、路由和代理设置，在签名一致的构建上覆盖安装，核对原数据和运行结果。签名不同时，用独立安装加备份恢复验证配置兼容，并单独标记覆盖安装的验证状态。
- **核心行为**用旧版和新版对照节点增删改、订阅、批量测速、路由、分应用代理、备份导入导出及常用外部入口。分别验证受支持的 VPN、仅代理和 Root 模式，Root 使用具备条件的单独环境。
